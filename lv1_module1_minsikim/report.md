# 문제1. 배달 로봇의 연산 분담과 실시간성 설계

배달로봇
- 2D 라이다(15Hz) (360point가정)
- RGB 카메라(60fps·720p)
- IMU(400Hz)
- 바퀴 엔코더(2kHz)
- 모터 드라이버
- LTE 모듈(핑 1~5ms, 95~100Mpbs)

작업 분류(임베디드/Edge AI/클라우드)

## 연산 분담 배치표 — 작업 / 위치 / 지연 예산 / 데이터량 / 근거 (6행)
|작업|분류|지연 예산|근거(명시되어있지않은 예산은 임의로 가정)|데이터 전송량|근거(명시되어있지않은 데이터양은 임의로 가정)|
|:---:|:---:|:---:|---|:---:|---|
|모터 속도 제어|임베디드|0.5ms|바퀴 엔코더의 제어속도(2kHz)|0.128Mbps|4B(float32) \*2 (엔코더 2개 가정) \* 2000(2kHz) = 16KB/s = 0.128Mbps|
|장애물 감지|Edge AI|120ms|라이다 데이터 갱신주기(15Hz->66ms) + 장애물 감지 처리(전처리20ms+감지30ms)|0.518Mbps|12B(x,y,z(float32)) \* 360(points) \* 15(15Hz) = 64.8KB/s ~= 0.518Mbps|
|보행자 인식|Edge AI|70ms|60fps(16.6ms)+보행자 인식 처리(전처리20ms+인식30ms)|1.5Gbps|1280\*720\*3(rgb)\*60(fps) ~= 166MB/s ~= 1.327Gbps|
|지도 기반 경로 계획|Edge AI|50ms|경로탐색30ms+후처리20ms|0Mbps|내부에서 처리|
|배달 완료 사진 업로드|클라우드|228ms|이미지크기(2764800B ~= 22.12Mbit) / LTE속도 100Mbps ~= 0.233s + 핑 최대 5ms|95Mbps|LTE속도 최악의 경우 95Mbps|
|운행 로그 집계|클라우드|100ms|로그 주기를 10Hz로 가정|0.008Mbps|로그데이터 100B가정(x,y위치, 시간, 속도, 베터리, 상태 등) \* 로그갱신주기 10Hz = 1000B/s ~= 0.008Mbps|

## 카메라 원시 영상 전송량: 1.25MB/s — LTE 대비 판단: 약 5초 소요

## 인지·판단·제어 계층 매핑과 주기표
|계층|인지/판단/제어|주기|hard/soft/firm|
|---|---|---|---|
|장애물 감지|인지|150ms|soft|
|신호등 감지|인지|83ms|soft|
|보행자인식|인지|83ms|soft|
|차량 인식|인지|83ms|soft|
|위치 추정|인지|83ms|firm|
|지도기반 경로계획|판단|50ms|firm|
|목표위치로 가는 속도 결정(각속도, 선속도)|판단|50ms|firm|
|모터 제어|제어|1ms|hard|

## Hard / Firm / Soft 분류표 — Hard 항목의 마감 초과 결과
모터 제어 (Hard, 1ms)
마감시간 1ms를 초과하면 해당 제어 주기를 놓치게 되며, 지속적으로 deadline을 놓칠 경우 로봇의 속도·자세 제어가 불안정해지고 안전 문제가 발생할 수 있다.

## 주기 · 지연 · 지터 구분 — 각 한 문장
주기: 다음 작업까지 실행되는 시간
지연: 인풋이 들어오고 아웃풋이 나오는 시간
지터: 주기나 지연의 변동하는 정도
